# 07. 운영·윤리·법적 고려사항

저장소: https://github.com/Benji5526/ai-persona-sns-automation

이 시스템은 기술적으로는 충분히 구현 가능하지만, **플랫폼 정책·초상권·소비자 보호 규제**와
맞닿는 지점이 많습니다. 설계 초기에 반영해야 나중에 파이프라인을 뜯어고치지 않아도 됩니다.

## 1. 플랫폼 자동화 정책

- 각 SNS의 API 이용약관은 "자동 대량 발송/댓글/DM"에 대한 제한을 명시하는 경우가 많음 → 공식 API·공식 자동화 프로그램(비즈니스 메시징 API 등) 우선 검토
- 비공식(스크래핑/역엔지니어링 기반) 자동화는 계정 정지·법적 리스크가 있으므로 지양
- 플랫폼별 "AI 생성 콘텐츠 라벨링" 기능(있는 경우) 적용 검토

## 2. AI 생성/합성 콘텐츠 고지

- 다수 국가·플랫폼에서 AI 생성 이미지/영상, 특히 실존 인물과 유사한 합성물에 대해 **표시(라벨링) 의무** 관련 규제가 강화되는 추세
  (예: 딥페이크/합성 미디어 관련 국내외 입법, 플랫폼 자체 정책)
- 설계 원칙: [06-data-model.md](06-data-model.md)의 `asset.source` 필드처럼 **무엇이 합성물인지 항상 추적 가능**하게 하고,
  필요 시 즉시 라벨링을 켤 수 있는 구조로 설계
- 페르소나가 "실존 인물처럼" 사람들과 상호작용(DM/댓글)할 경우, 계정 소개/고정 게시물 등에 가상 캐릭터임을
  고지하는 방식을 사업적으로 검토 (완전 비공개 운영은 규제 리스크가 더 큼)

## 3. UGC 페이스스왑 관련 초상권

- [04-faceswap-ugc.md](04-faceswap-ugc.md)의 권리 확인 게이트가 핵심 방어선
- "영상 사용권 구매" ≠ "해당 영상 속 인물 얼굴을 교체할 권리" — 계약서에 **합성/변형 후 재배포**가 명시적으로 포함되는지 반드시 확인
- 라이선스 범위가 모호한 소스는 법률 검토 없이 파이프라인에 투입하지 않음

## 4. 개인정보/대화 데이터

- DM/댓글 대화 이력에는 개인정보가 포함될 수 있음 → 보관 기간, 접근 권한, 파기 정책을 사전에 정의
- 페르소나 학습에 사용하는 레퍼런스 이미지가 본인 소유가 아닌 경우, 별도의 사용 동의/라이선스 확보 필요

## 5. 상업적 표시 규제

- 홍보/판매 목적의 콘텐츠라면 광고 표시 의무(협찬/광고 표기 등) 준수
- 페르소나를 통한 판매 유도 대화(DM)의 경우, 소비자 보호 관련 고지 의무 여부 검토

## 6. 설계에 반영된 완화 장치 요약

| 리스크 | 완화 장치 (관련 문서) |
|---|---|
| 스팸/계정 정지 | 휴먼라이크 스케줄러의 동시성/총량 상한 ([01](01-reply-automation.md)) |
| 무단 초상권 사용 | UGC 권리 확인 게이트 + 라이선스 레코드 강제 연결 ([04](04-faceswap-ugc.md), [06](06-data-model.md)) |
| 저품질/오작동 콘텐츠 확산 | QC 게이트 (자동+수동) ([03](03-content-pipeline.md), [04](04-faceswap-ugc.md)) |
| 합성물 은폐 | 에셋 메타데이터에 `source` 항상 기록, 라벨링 스위치 구조 ([06](06-data-model.md)) |
| 완전 자동 발행 리스크 | 반자동(승인 후 발행)으로 단계적 도입 ([05](05-auto-posting.md), [08](08-roadmap.md)) |

> 이 문서는 일반적인 설계 가이드이며 법률 자문을 대체하지 않습니다.
> 실제 운영 전 관할 지역(예: 대한민국)의 개인정보보호법, 정보통신망법, 표시광고법,
> 그리고 딥페이크/합성 콘텐츠 관련 최신 규제를 변호사와 함께 검토하는 것을 권장합니다.
